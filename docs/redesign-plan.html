mayankd.me rebuild — plan

Working doc on the redesign branch. The old site keeps deploying from dev until Phase 1 ships. Companion file: ui-scaffold.html — the visual half of this plan, meant to be opened in a browser and argued with.

1. Why the site gets rebuilt#

The current site runs on a framework that stopped moving in 2023, on a 2020 template that keeps biting.

The stack is Gatsby 3 on React 17. Gatsby has been in maintenance since Netlify absorbed the team, and npm audit reports 89 findings against the dependency tree. None of that is an emergency for a static site, but every hour spent on it goes into keeping an old framework alive, and the interactive labs I want to build would fight it the whole way.

The design has a second problem: it started as Brittany Chiang's dark-navy v4 template and was hand-converted to a cream light theme. The conversion left dark-theme assumptions buried in the CSS. Three separate bugs on the featured-project covers traced back to that half-converted state, including white-on-cream text at 1.08:1 contrast. I also just don't like the cream theme anymore.

Decisions were locked on 2026-08-07: Astro 5, dual theme with dark as default, a single dense homepage with a command palette, GitHub Pages stays. REDESIGN.md in this folder holds the token-level spec; this doc holds the full plan.

2. The stack: Astro 5#

Astro because the site is mostly content, and the parts that aren't content should be islands.

LayerChoiceReason
FrameworkAstro 5 + TypeScriptContent collections give the existing content/ markdown typed schemas. Pages ship zero JS unless a component asks for it.
Interactive bitsReact 19 islandsCommand palette (cmdk), theme toggle, lab embeds. Nothing else hydrates.
StylingTailwind CSS v4Tokens live in one @theme block. shadcn/ui primitives inside islands where they earn their place.
PostsMDXInteractive widgets inline with prose, the way Maxime Heckel's articles work.
MotionMotion + Astro view transitions150–250 ms, ease-out, honors prefers-reduced-motion.
HostingGitHub Pages, same CNAMEDNS already works. Cloudflare Pages becomes interesting only when a lab needs a Worker proxy.

Why not Next.js, which is what eddyhdzg.com and Brittany's v5 use: it wants Vercel to shine, it ships a React runtime that plain content pages don't need, and every pattern I want from those sites (palette, cards, heatmap) works the same inside an Astro island. I'm not applying for frontend jobs; the stack should serve the labs and the writing.

Carry-overs from operating the old site The build must emit CNAME (in Astro: public/CNAME). The domain 404'd for an hour once because CNAME lived only in committed build output. Lockfile gets committed from day one and CI installs with npm ci — the old site broke after 15 months of floating dependencies. Node version pinned in .nvmrc, CI reads it from there.

3. The look: dark, one accent, Geist#

Dark by default, one azure accent, Geist type, and a point-cloud motif because that's the actual job.

Type is Geist Sans for everything readable and Geist Mono for metadata, labels, and code. Both are free and self-hosted as woff2. The accent values are mine, picked in the family of Maxime Heckel's blues — his exact tokens render behind JS and weren't worth chasing, and copying hexes was never the point.

The one visual signature is a point-cloud canvas in the hero: drifting points that occasionally organize into a box wireframe and let go again. Plain 2D canvas, under 15 KB of script, static scatter for anyone with reduced motion. Three.js never loads on the homepage; it belongs to the labs. Homepage hydrated JS stays under 100 KB total.

Contrast floor is 4.5:1 for body text and 3:1 for large text, checked at review time on every color pair. The old site shipped invisible text twice. Not again.

4. Navigation people don't have to think about#

A visitor should know who I am in five seconds and reach anything on the site in one or two clicks, without learning anything.

The research behind this section is Nielsen Norman Group material on recognition versus recall and "you are here" cues. The short version: people pick from what they can see far more easily than they remember what exists, and a site has to keep telling them where they currently are.

What that means concretely

  • Visible, labeled nav. Text links on desktop — About, Experience, Labs, Writing — plus a Resume button. No icon-only navigation, no hamburger above 768 px.
  • The ⌘K palette is an accelerator, never the only path. Everything the palette reaches is also reachable through a visible link. Search supplements browsing; it doesn't replace it.
  • You-are-here cues. The nav highlights the section currently in view as you scroll. Every route gets a distinct page title. URLs stay readable. The name in the top-left always goes home.
  • The five-second test. Name, role, employer, and the resume button all sit above the fold. A recruiter arriving cold should not have to scroll to learn who I am.
  • Resume is one click from anywhere. Nav button, palette entry, footer link — all point at the same /resume.pdf.
  • Mobile is not an afterthought. Tap targets at 44 px minimum, nothing hidden behind hover, menu reachable by thumb, layout tested at 360 px wide.
  • And speed. Static HTML with actual content in it (the old homepage shipped an empty loader div), fonts with font-display: swap, no layout shift.

The test worth running after Phase 1: show someone a single page cold and ask "where are you on this site?" If they can't answer from the visible cues, the cues are too subtle.

6. One site repo, one repo per lab#

This repo becomes shell and hosting only. Every lab lives in its own repo and hands the site either data or a built bundle.

Keeping lab code out of the site repo means a lab can have its own CI, its own secrets, its own release pace, and a README that stands alone — each one is a portfolio piece in repo form too. The site consumes labs through two narrow contracts:

RepoWhat lives thereWhat the site consumes
MayankD409.github.ioAstro site, content, hosting, this docs folder—
fund-of-oneTrading agent, Actions cron, guardrails, memo historyJSON fetched client-side from the repo's raw files. GitHub serves those with open CORS, so the fund page stays current without rebuilding the site.
sensor-labDepth-model demo: webcam to point cloud to geometry togglesA built static bundle, vendored into /labs/sensor-lab/ at site build time.
mini-unloaderSynthetic container scene with the staged perception pipelineSame bundle contract as sensor-lab.

API keys (Alpaca, LLM) exist only as Actions secrets in the lab repos. The site never holds a secret and never talks to a paid API from the browser.

7. The plan, phase by phase#

Phase 1 replaces the stack and the UI. Every phase after that is one lab. The shell gets four weekends, hard cap.

Phase 0 — setup done

legacy-gatsby branch frozen at the last Gatsby commit. Work happens on redesign. This doc and the scaffold live in docs/.

Phase 1 — stack + UI next

  1. Iterate on ui-scaffold.html until the design feels right in the browser. Cheap to change now, expensive later.
  2. Scaffold Astro 5 with Tailwind v4, the token file, and both themes.
  3. Port content/ into typed collections: jobs, projects, featured, posts.
  4. Build the components: nav with active-section highlight, palette, hero canvas, experience timeline, labs grid, projects (four featured, the rest behind a show-all toggle), writing list, the fixed social rail, footer.
  5. SEO carry-over, item by item: JSON-LD person (job title, Contoro, the msdeshpande04 LinkedIn), Google verification meta, analytics tag, sitemap, robots, CNAME emission, og image regenerated in the new brand, 404 page.
  6. Parity QA: every old route resolves or redirects (/blog/* slugs unchanged, /pensieve/* redirects to /blog), Lighthouse 95+ on mobile and desktop, the five-second test on a stranger.
  7. Swap: point the deploy workflow at the Astro build, merge to dev, verify the live domain, resume, and structured data. Tag the old site.

Definition of done: the new site is live on mayankd.me with nothing lost — every URL, every meta tag, the resume, the domain.

Phase 2 — Fund-of-One own repo

An autonomous paper-trading fund with a public audit trail. A GitHub Actions cron runs before market open: pull prices and headlines, have the agent write a decision memo, execute through Alpaca's paper API, commit portfolio state and memo as JSON. The site's fund page renders the equity curve against SPY, current holdings, risk numbers, and the full memo archive. Guardrails — position caps, no leverage, a kill switch — are part of the exhibit.

This phase can start before Phase 1 finishes. Its value grows with calendar time: a fund that has been running for six months with every decision logged is a different artifact from a demo finished yesterday. Real brokerages stay out of it — Robinhood has no official API, and paper trading is the honest version anyway.

Phase 3 — Live Sensor Lab own repo

Your room as a robot sees it. Webcam frames run through a small depth model in the browser (WebGPU, WASM fallback), get back-projected into a point cloud you can orbit, and then the real content starts: RANSAC plane extraction, clustering, voxel downsampling, a flying-pixel filter at depth edges, simulated dropout on dark surfaces — each one a toggle with a sentence on why it matters on a real robot. A bundled sample clip covers visitors who skip the camera permission.

Phase 4 — Mini Unloader own repo

A miniature of the day job, built from public parts. A synthetic shipping container with randomized box piles, a rendered depth camera, and the pipeline shown stage by stage: raw cloud, planes, instances, pick pose, arm executes, repeat until empty. The panel that sells it: break the sensor on purpose — noise, dropout, a two-degree calibration tilt — and watch which stage fails.

Phase 5 — stretch

Poke-the-Robot (a browser physics sim with a trained locomotion policy you can shove), Click-to-Measure (segment an object, get metric dimensions from the fitted plane), and a site chatbot over the lab writeups once there are enough of them to be worth asking about.

8. Rules that don't bend#

Nothing from Contoro, ever No data, models, meshes, parameters, or scene geometry from work appears in anything public. Labs use synthetic scenes and public datasets, built on personal time and hardware.
  • Homepage hydrated JS under 100 KB. Three.js loads only inside labs.
  • Every color pair gets a contrast check at review. 4.5:1 body, 3:1 large.
  • Site copy is written in my site voice — casual, with asides. Not resume voice, not PR voice. Any text that reads machine-written gets rewritten before it ships.
  • The four-weekend cap on Phase 1 is real. If it hits, ship what exists and move to the labs — they're the part nobody else has.
